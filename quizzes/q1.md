Module 2: NodeJS Core

    What Node.js is: V8 engine execution outside the browser with an event-driven, non-blocking I/O model.

    Synchronous vs. Asynchronous Execution

        Synchronous: Code executes sequentially, line by line. Each operation must fully finish before the next one starts. A long-running task (e.g., reading a large file) blocks all subsequent code from executing.

        Asynchronous: Long-running tasks (e.g., file I/O, network requests) are handed off to run in the background, allowing the main program to keep running without blocking. The result is handled once ready using callbacks, Promises, or async/await.

    Handling Asynchronous Code

        Callbacks: A function passed as an argument to an asynchronous operation, invoked automatically once that operation completes.

        Promises: An object representing the eventual outcome of an asynchronous operation. Returned immediately, it acts as a placeholder; its resolved value becomes accessible only after the operation settles.

        async/await: Syntactic sugar built on top of Promises. The await keyword pauses execution inside an async function until the Promise settles and directly unwraps its resolved value.  Without await, an expression evaluates to the pending Promise object itself rather than the resolved result.

    CommonJS (require / module.exports) vs. ES Modules (import / export).

    Dependency management: package.json dependencies vs. devDependencies.

Module 3: Web Server & Express Framework

    HTTP Request/Response lifecycle: Clients, Servers, HTTP Headers, Method verbs, Status Codes.

    Express routing setup (app.get(), app.post(), app.put(), app.delete()).

    Extracting input: req.params (URL parameters), req.query (Query parameters), req.body (JSON payload requiring express.json()).

    Middleware Flow: Purpose of next(), execution order, and custom middleware handlers.

    Error Handling: Recognizing the standard 4-parameter Express error signature (err, req, res, next).

Module 4: REST API & Layered Architecture

    RESTful Standards:

        Use plural nouns for resource endpoints (/api/posts), NOT verbs in URL paths (/api/getPosts).
        GET, PUT, and DELETE are idempotent (repeated identical calls produce the same server state). POST is NOT idempotent.

    HTTP Status Code Conventions

        200 OK (Standard success response)

        201 Created (Resource successfully created via POST)

        400 Bad Request (Client-side validation failure)

        404 Not Found (Resource does not exist)

        500 Internal Server Error (Unhandled server error)
    Layered Architecture Separation of Concerns:
        Validation Middleware: Custom middleware functions can inspect incoming payloads (req.body, req.params, req.query) before reaching the controller. If validation fails, the middleware terminates the request immediately with a 400 Bad Request status and does not call next()

        Controller Layer: Handles HTTP concerns (req, res), status codes, and input extraction.

        Service Layer: Houses core business logic, rules, and calculations.

        Repository / Data Access Layer: Manages operations on the in-memory array.

    Query Handling: Basic implementation of filtering, searching, sorting, and pagination.
